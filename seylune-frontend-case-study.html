Case 03 / Full-stack website / 2026

Seylune,
luxury fashion store.

A fictional Sri Lankan-inspired fashion house. It began as a university frontend, then came back as version two: a new face in the same moonlit colours, a new structure, and a Supabase backend with real accounts, orders, live stock, an admin dashboard and customer profiles.

  • Full-stack
  • Supabase
  • E-commerce UI
  • Admin dashboard
  • HTML / CSS / JS
  • AI-assisted

StackHTML, CSS, JS + Supabase
Catalogue40 pieces, 6 collections
RoleDirection, design, build
01 Project context

A class website that became a working store.

Version one was built for the SLIIT Internet Application Development assignment: a fashion frontend with no backend, where the cart and orders lived only in the browser.

Once the marking was done, I rebuilt it. New face, same colours, a new structure, two new collections and a real backend: sign-up and sign-in, orders saved in a database, stock that goes down when someone buys, and an admin side to run the shop. Seylune is still not a real business. No payment is taken and nothing is shipped.

Truth 02

03 Visual direction

Same moonlit colours. A new face.

The palette stayed exactly as it was. Everything around it changed: engraved capitals in Tenor Sans, quiet Manrope for reading, square-cut edges, and antique gold kept for one job only, marking what is chosen, what costs money and what to do next.

Decision 01

Rooms, not pages

Every inner page splits in two: one half holds still while the other moves.

Decision 02

Liquid photographs

Pictures melt from one piece to the next in WebGL, with a plain image fallback.

Decision 03

The clothes lead

No sale banners or fake urgency. The interface recedes around the photography.

04 New structure

A house of scenes and rooms.

Home became six full-screen scenes, one flick of the wheel each. Every other page is a room. Fifteen pages now: home, collections, new arrivals, five categories, product, search, cart, checkout, account, about and admin.

Route 01

Enter

Six scenes set the mood before any shopping starts.

Route 02

Browse

A numbered index; pointing at a name melts the photo into it.

Route 03

Inspect

Gallery, zoom, size guide and live stock for every size.

Route 04

Buy

Bag drawer, cart and a checkout that saves a real order.

Route 05

Run

The admin room handles orders, pieces, stock and messages.

05 Homepage

Six scenes instead of a scrolling page.

Each scene dissolves into the next: the entrance, new arrivals, the categories, the story, the signature edits and the newsletter.

06 Collections

Two new rooms: Outerwear and Accessories.

Sixteen new pieces joined Dresses, Tops and Bottoms, for forty in all. A Collections page gathers the six rooms, and every room has filters for size, colour and price.

07 Shopping flow

From the menu to a saved order.

A full-screen menu with search, a bag drawer that opens beside the piece, a cart that keeps sizes apart, and a checkout that asks you to sign in so the order follows you to any device.

08 The backend

A static site with a real database behind it.

The pages still run on GitHub Pages. The browser talks straight to Supabase, and rules inside the database decide what each visitor may see or change. The browser never sends a price: the database looks it up itself.

Supabase 01

Real accounts

Sign up, sign in and password reset through Supabase Auth.

Supabase 02

Orders priced by the database

One database function checks every field, prices the order and takes the pieces out of stock.

Supabase 03

Live stock per size

Sold-out sizes are struck through, and a sale price must sit below the price.

Supabase 04

Row Level Security

Customers read only their own orders; only admins can change status, stock or prices.

Supabase 05

Messages and newsletter

Anyone can write in, a few times every ten minutes; only admins can read them.

Supabase 06

Safe fallback

If the database can't be reached, the shop falls back to its built-in catalogue.

09 Admin dashboard

A back room to run the shop.

Only accounts on the admin team can open it. Six tabs cover the whole shop: sales at a glance, orders, pieces, stock, customers and messages.

Track

Order status

Processing, shipped, delivered. Cancelling puts the pieces back into stock.

Add and edit

The catalogue

New pieces, photo uploads, sale prices, and archiving old ones.

Stock

Low or sold out

Every size of every piece, with a filter for what is low or sold out.

Inbox

Messages

The contact form lands here, sorted into new and done.

10 Customer profile

An account that remembers you.

Members keep their details, which fill in checkout for them, change their password, follow each order's status and come back to the pieces they saved. Only they can read their own profile.

11 Workflow and tools

AI as an assistant, not a fake credit.

Claude helped write and iterate the code, including the database rules; Gemini and Nano Banana generated the model imagery. Direction, structure, page decisions, edits and polish were mine.

Tool 01

HTML, CSS, JS

Plain pages with no build step, one shared catalogue and shared shop logic.

Tool 02

GSAP and WebGL

Scene dissolves and liquid photographs, all switched off for reduced motion.

Tool 03

Supabase

Postgres, Auth, Storage and Row Level Security behind a static site.

Tool 04

AI workflow

Claude for code, Gemini and Nano Banana for visuals.

12 Reflection

Version one proved Seylune could look like a fashion house. Version two proves it can work like a shop, from the first scene to the back room.

01

Keep what works

The palette and the name carried over; the structure did not need to.

02

Trust the database

Prices, stock and permissions are checked where a visitor can't edit them.

03

Design the back room too

The admin side got the same care as the storefront.

04

Next step

Email confirmation for new accounts and a real payment step.
